# 全量追溯与交叉修订

先保存任务初衷和初稿哈希，再做逐项复盘。全量追溯指所有实证链条得到核对或明确标出缺口，不等于无条件重估所有模型。默认复用可核验的既有输出，只对缺失、冲突、必要补充或用户要求的部分重跑。

清单至少包含：原位置、主张/假设、数据文件与哈希、清洗脚本、变量定义、分析单位、筛选条件、缺失规则、样本指纹、模型规格、估计状态、参数与区间、输出对象、表图位置、精简处置及剩余缺口。同段多个主张要分别映射，不能用一个“整节已核对”覆盖所有结果。

1. `inventory` 从不可变初稿生成机械清单。人工复核表题、图题、脚注、公式、正文和附录尾节；为每个实证论断建立 claim 节点。
2. 依赖图按 data → cleaning → variable/sample → model → output → table/figure → claim 建立。保存输入、脚本、规格和输出指纹。原始输入只读。
3. 记录 `traceability=unique_source|compatible_candidates|documented_partial`。相容的多个候选输出不能声称唯一来源；有明确 partial 的稿件必须保留解释和接受依据。
4. 对有效样本、夫妻角色与镜像、波次/组别及分母做独立核对。夫妻镜像不构成第二份独立证据；两端点各自显著不等于差值显著。
5. 分离存储精度（例如 Stata binary32）、显示舍入、比较容差、区间算法（BC/percentile）和抽样数量。请求抽样数、保存抽样数、有效抽样数、逐次收敛不可互换。
6. 保留反例、未达判据结果和限制。撤图、合表或删段时，写清数值移到哪里、结论如何保留。不能通过删除矛盾结果来使文稿更“简洁”。

NLM 报告数值或图文冲突时，先把原话、引用和页码保存为 issue，路由到本地依赖图复查。可核对输出时不重新估计；须补核才按已有授权执行。确认错误后生成后继文稿并失效受影响的导出与审查；误报则保留原回答和反证。

恢复任务时读取 checkpoint，不依靠上一轮摘要猜版本。记录当前安全阶段、执行模式、不可修改路径、进行中的 job/session/PID、未决问题及每份文档的有效哈希。先收取原作业，不能因 `running`、输出短暂不变或上下文压缩而重复提交。
