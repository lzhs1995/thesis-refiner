# 文件管理与复现结果的采用边界

当用户要求将既有论文档案扩展到历史数据或代码时，先固定此次范围：文件管理、隔离复现、科学裁决和成品修订分别记录。已有脚本产生不同数值，不自动形成替换论文采用数据或重新估计下游模型的授权。

## 有限交付

- 列原始路径、隔离路径、版本与哈希来源；区分本次计算的哈希和历史记录的哈希。
- 记录代码输入输出关系、已有回执、成功、失败、未执行和采用不明项。路径数量包含副本与输出时明确说明，不能当作独立原始数据数量。
- 静态导入语句只证明代码含该表达式。动态变量、工作目录和实际运行采用需要另外的证据；软件包示例、工具环境与研究脚本分开导航。
- 新复现与历史采用输入有差异时，附Markdown说明差异、依据及不确定性，交作者裁决；不要求所有差异消失后才能交付文件管理包。
- 已产生的独立后继版本保留并登记采用状态；不得静默覆盖基线，也不为纠正范围删除失败证据。

## 接续与协作

用户纠正范围后，通知原执行者在安全边界停止尚未提交的扩展阶段。投递、消费和执行停止分开核实；通知入队不等于原执行者已经停止。在途操作由原owner保全至真实终态，不能强杀共享服务或替他清票。

当成品已冻结，工具修复、并发验证和版本维护独立记录。不得因工具经验尚待验证，自动给论文追加审读、重估或音频重制任务。用户明确仍要求的工具验证继续作为待办，不冒称通过，也不阻挡已满足条件的档案交付。

外部审阅包应包含可直接读取的索引及说明，写清实际附带的内容。绝对路径对远端聊天并不意味着可访问；源文件未附带时标记覆盖缺口，不以清单或SHA核对替代内容审查。
