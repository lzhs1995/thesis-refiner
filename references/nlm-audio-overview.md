# NLM 音频概览：从冻结材料到本地成品

仅在用户要求音频时进入本流程。音频是已审材料的衍生成果，不是论文审校轮次，也不自动授予三审三校信用。先消费已通过验收的论文/PPT文稿、演示文件和逐字稿版本；用户只选其中若干材料时，严格保持该来源集合。论文可以随成果归档，不因此自动成为音频来源。

## 固定输入与参数

1. 记录本地文件绝对路径、哈希、notebook ID、真实 source ID、对应上传或复用证据。先查重；同 notebook、同版本的既有来源可复用。不要因开始新一轮或换了执行者再次上传。
2. 上传成功后核来源身份及完整抽取文本，参照 [全文核验](nlm-review-and-budget.md#全文输出丢失身份字段)。按页、段落或表格内容定位缺失；DOCX 抽取中夹入字体名不等于正文丢失，整篇连续字符串不匹配也不能直接判漏读。图像能上传不证明图中数字已被识别，涉及结论的表值和图注另核。来源 READY 与正文覆盖分别记录。
3. 固定用户指定的 format、language、length 和完整 focus prompt，保留换行与版本。以已安装工具的版本、帮助和实际请求为准，核验请求中所有生效的来源列表与参数，不只核本地计划。用生成命令的语言参数，避免为单项任务修改账号全局语言。`default` 是长度档位，不是固定分钟数。
4. 明确本次允许的生成次数；用户只要一段时，成功受理一次即达到创建上限。问答、音频、影片分别记调用数；套餐次数或 compute 规则的来源和观测时间另存，不把旧套餐表或用户提供的数值硬编码成永久官方上限。

跨章节复用已经验证的执行流程时，保留成功的请求、下载和验收逻辑，在新任务的私有副本中适配实际账号/profile、notebook、执行者、transport、来源与输出文件绑定。先验证新入口能被当前执行者消费，并逐项核当前版本素材；旧章节的 source/artifact ID、创建回执和审校通过状态不能随脚本复制。离线适配完成只记准备就绪，实际新来源与新成品仍以本次真实返回为准。

## 创建、等待与下载

创建前保存原始请求身份和源/参数指纹；收到真实返回后立即保存唯一 artifact ID。请求可能已受理但本地响应丢失时，核原请求和既有 Studio 记录；没有明确的零发送证据，不能自动再 create。

创建 RPC 已完整收回、子进程与传输资源排空后归还网络窗口。后台生成可以继续，状态检查按当前准入规则取得短窗、读取原 artifact、归还后再等待；不把整个生成时长变成账号独占窗口。15–30 秒可作观察起点，按实际耗时与服务提示调整，并保存可恢复的观察进度。主会话持续推进离线工作。

| 观察到的事实 | 后续动作与完成含义 |
|---|---|
| 有 artifact ID，状态 pending/in_progress | 保留原 ID，继续观察；尚未生成完成 |
| SDK 返回 unknown，或尚无下载地址 | 保存原始状态与响应；不是成功、失败或额度耗尽的充分证据 |
| 原 artifact 的实际完成状态与媒体信息已核 | 下载该 ID 对应的音频；不按“最近一条”选别人的成果 |
| CDN 暂时 404、签名地址过期或下载中断 | 在原下载预算内重查同一 artifact 的媒体地址，做有界下载重试；不重新生成 |
| 明确生成失败 | 保存原失败与已用次数，继续其他本地交付；新生成必须有必要原因及尚有效的授权/预算 |
| 原网络终态未知 | 处理原请求与隔离，不把本地等待结束当释放证据 |

等待器退出、会话重启或通知失败均不改变服务端成品状态。恢复时先读已保存的 artifact ID、原始 create 回执、最近状态和本地下载文件；文件已经存在就核对哈希及媒体完整性，不覆盖重下。重取媒体地址与重新 create 分开计数。

## 验收与统一归档

已有 artifact 后发生执行者继任时，可用 [阶段限定恢复契约](audio-recovery-contract.md) 离线核准原成品的观察/下载入口。它只检查固定身份和证据，不授予账号、应用或新创建权限。

分别保存以下证据，不能用一个 `success` 覆盖全部状态：

- 来源与参数：本地冻结版本、真实来源身份、全文核验、实际创建请求的来源集合和参数一致。
- 服务端与下载：原 artifact 已完成，下载指向该成品，文件非空且哈希和字节数已记录。
- 媒体完整性：在 macOS 用 `afinfo` 读取时长、编码与声道，再用 `afconvert` 完整解码，检查退出码与可解码时长。其他平台用等价工具。临时 PCM 是否保留另记，不复制进成果目录充数。
- 内容审听：是否实际听审、转录、逐句对照，单独记录范围。哈希与解码通过不能宣称四项 focus 都被充分讲解，也不能证明语言、数值和论断无误；参数设置正确与实际内容正确分开报告。
- 资源与交付：本次调用已真实归还；论文、文稿、PPT、逐字稿和音频按用户指定目录归档，保留既有文件，给绝对路径与清单。用户指定的目录名即使与章节号不同，也不擅自更名。

复查已有成品时，当前文件与冻结哈希一致，可以复用绑定该版本的原审校、视觉与解码证据，补核本次检查的范围。不得为出具“最新回执”重复生成音频或重跑已完成的 NLM 审校。

用户另要求内容核对且当前接口不能直接接收音频时，可在已有授权内使用本地转录，再对照同版材料核读。复用同一音频和已验证解码文件，记录转录模型/版本、时间戳与不确定片段；已有转录任务先核其原进程和输出，不因迟迟未完成重新启动。机器转录核读不等于实际听审，ASR 的数字、否定词或术语错字也不能直接裁定为音频事实错误。此步骤不自动追加到每次音频交付。

同模型换分段窗口的复识仍是相关证据；记录是否输入了论文原句或提示，不能计作独立听审。可选 ASR 预检须区分模型特定的 `alignment_heads` 索引元数据与学习权重 shape；遇版本兼容问题先核对应模型实现及原失败，不为一次错配随意改权重或宣称音频有错。

Critique 中的表达建议、事实判断和未来研究设想分别核对。“原稿应补充某说明”先查同版文稿是否已经说明；不能只据音频评论再改稿或加审。算法收敛、聚类编号、测量约束、分类误差和因果识别是不同问题，按论文实际报告逐项区分；focus 提到收敛警告，不证明论文存在算法不收敛。类比和政策设想不能提升原结果的因果或机制结论强度。

并发与限额沿 [既有调度规则](nlm-concurrency-and-scheduling.md)；真实认证失效按 [同账号恢复](nlm-auth-recovery.md)。通用文档不保存账号、真实 notebook/artifact ID、认证数据、签名媒体 URL 或章节私有路径；这些留在任务证据目录。
