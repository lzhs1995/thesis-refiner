# 论文任务中的协作提效与收尾

本页补充[协作、租约与恢复](collaboration-and-recovery.md)；
通用握手与发送实现仍由 multi-agent-collaboration 维护。

- **按收益分工。** 一人可快速完成的整理直接执行；有独立的引文溯源、
  统计输出核查或工具审查时再派给一个或两个已授权 executor。
  每人有独立任务包、nonce、输出目录和完成条件；共享文稿、公共脚本
  只有一个整合写入者。Word/Zotero 等原生资源仍按原队列串行。
  没有独立待办时允许待命，不为显示活跃重估模型或重复审稿。
- **接续时核实际任务归属。** 实时 caller/workspace、原 role-map 与执行者
  当前任务必须对应；标题或旧摘要不能替代。正在审其他章节或另一项目的
  Claude 记为“另有任务”，不插入新任务、不称其故障。原绑定跨工作区时，
  沿已有 SOLO 授权继续本任务独立工作，保留原会话和任务包，不借用他方执行者。
  进度说明当前零、一或两个 executor 的具体原因；在下一次实际派单或既有
  阶段边界再核可用性，不另建监控循环，也不永久沿用旧故障判断。
- **握手只验证通道。** 直接给绝对 pending receipt 和固定完整 skill；
  不在 ACK 前要求业务审计。使用 `--handshake-timeout 600` 或更长预算，
  不用泛化 `--timeout` 覆盖相位预算；有效 ACK 到达立即继续，
  同任务健康握手复用。预算不足或检测器漏观测不能归因 Claude 失效。
- **prompt 与 callback 都核发送后证据。** 原 bridge 每次写入前核当前
  workspace/surface UUID，Enter 后核完整消息与原 marker。compose、
  queued、实际消费、正式 receipt、报告接受分列。unknown 只读核原 attempt，
  不重贴、不循环按键、不删 journal。报告已读取不能伪造 callback receipt。
- **报告完成就沿原入口回调。** 不额外等待 supervisor 空闲，不建秒级
  watcher；由原 bridge 判定输入区及既有补键条件。supervisor 可读固定
  报告并推进不依赖传输回执的工作，回执缺失如实保留。
- **故障不拖住全篇。** 原生 reconnect/正常执行不打断；provider 可重试
  故障仅在原尝试终态后按既有上限恢复，认证/欠费不盲试。持续失效时
  沿已有接管授权保留原会话和证据、确认无并发写入，再由 Codex 继续。
  自审标 `solo_self_review`；恢复协作只在同一会话及安全边界交回。
- **已接受成果及时结案。** 论文修订、原生检查、审读反馈、传输核收、
  用户验收分别记账。已接受章节或局部工具故障不因经验维护重新开审；
  剩余论文主线另列。新改动只做相关增量核查，保留历史失败与纠正依据。

GitHub 文档更新、安装、客户端实际加载和研究结果验收是不同完成轴。
本页不授权重跑研究、重启会话、额外模型调用或绕过共享资源锁。

## 共享 daemon 与重复 TTY 的正确归因

共享后台可能继承另一终端的环境；以唯一存活的原生客户端、进程出生信息和
内核读取的 surface/workspace UUID 识别本方，再核该 UUID 对应的真实 TTY。
其他窗口残留同名 TTY 不得否决已明确的本方身份；重复 UUID、实际 TTY 不符、
进程漂移或跨 workspace 仍须拒绝。不得手工覆盖 CMUX 环境绕过核验。
这是 supervisor 客户端识别问题时，应准确说明，不能称“Claude 身份门禁失败”。

握手只做通道验证。空输入区的测试 token 按实际长度有界清理，保留逐键身份核验
与最终清空检查；有效 ACK 到达后立即派发，不为状态核查重复握手。两个指定
Claude 可分别核数据链条和工具补丁，独立目录并行计算；同 pane 两 tab 的输入
继续串行。原任务已经入站但检测器未确认时，只核原 journal，不重贴消息。

经验维护须落到新固定 release、实际启动器与 hook，再测安装入口。不能只改
SKILL 文案就宣称故障已修复，也不能把新配置当现役客户端已热加载。等待工具
审查期间继续实体归档核收；不因此增加模型估计、改稿或新的研究审轮。

## 文件管理任务以实体交付收尾

用户要求归档与复现材料整理时，先按章节提供真实数据、程序、初始化模板、模型
和表图，再写简短使用顺序与问题说明。大文件可提供已核验的本地压缩实体或网盘
位置、完整性校验及恢复步骤；不能只交审计Markdown/JSON，也不能把目录阅读顺序
写成整库执行许可。链接可用、文件身份、可迁移运行、历史采用和科学接受分别记录。

对接统计复盘者时，优先核收既有文件请求和结果。当前同名DTA/CSV的SHA一致，
只证明当前文件身份；它不证明旧模型实际使用该输入。保存数据框的逐格匹配也不
替代原执行日志，部分模型的匹配不能扩大为全部模型通过。输入覆盖、竞争版本或
历史缺项应逐项附注，沿用户文件管理范围交人工判断，不为补齐记录启动重估或
改写论文、PPT。用户指定核心程序与旧稿后处理来源分开导航，保留历史依据；
Windows与Mac资料按证据比较，不以所在平台决定优先级。

磁盘不足时主动处理已授权备份与清理，不停止全部工作。按用户空间底线及预计
产物预算准入；大模型逐件恢复，禁止为了核路径而展开整批模型。备份须实际回读
整包和全部内容；由原文件所有者核依赖后回收源，主管核回执并清理自有终态缓存。
已由所有者清理的源不重复删除。实际可用空间与逻辑/克隆大小分列，压缩未释放
空间的失败原样保留，不批量重复。唯一源、现役数据库与运行依赖继续保护。

归档完成、统计插件验收、回调结算和工具维护分列完成条件。后继导航文字不属于
已经上传的旧快照；说明其时间边界即可，不因每次状态更新循环打包、重审或重跑。
# Codex 队列显示误判（2026-10-08）

实测 `• Queued follow-up inputs` 标题在回调正文上方，而编辑队列提示在正文下方；只从下方提示寻找 nonce 会误报 COMPOSE_OCCUPIED。协作桥须识别实际队列区域，并在下一个输入框前停止匹配，不能把草稿或先前对话中的 nonce 当排队证据。

Enter 后仍在输入框、执行界面明确提示的一次 Tab 后进入队列、接收端消费、报告核收分别记录。队列状态仍是 pending，不等于回调成功，也不能重贴或重握手。沿原 journal 核收；主管同时继续独立主线。此类本地误判不归因 Claude API，不通过加长握手等待解决。

复用 multi-agent-collaboration 的 `references/queued-followup-inputs.md` 和 `scripts/test_queued_followup.py`，不在论文技能复制发送器。源码、离线测试、实际安装、现场双向验收分别汇报；在途任务保持原绑定。
