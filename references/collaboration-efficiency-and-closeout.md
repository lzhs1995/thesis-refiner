# 论文任务中的协作提效与收尾

本页补充[协作、租约与恢复](collaboration-and-recovery.md)；
通用握手与发送实现仍由 multi-agent-collaboration 维护；通信、恢复与等待遵循[统一合同](verified-compose-delivery.md)。

双方 prompt 就绪后立即经支持入口发送，正常执行、原生 `/goal` 和自动续轮均不
要求暂停或等待空闲。接收方自行协调任务顺序；共享写入的交接不限制通信。
当前新握手不运行强制探针，详见协作仓的
[忙碌时双向通信](https://github.com/lzhs1995/multi-agent-collaboration/blob/main/references/busy-bidirectional-communication.md)。

哨兵 `SENTINEL_ROLE_MAP_REFUSED` 先按
[协作 skill 的角色表兼容规则](https://github.com/lzhs1995/multi-agent-collaboration/blob/main/references/efficiency-and-closeout.md#哨兵启动失败先核角色表格式)
核 `surface_ref`/`identity` 与单个/多个执行者的实际格式。复用该仓的唯一解析器，
不在论文 skill 复制一套；监控启动失败不等于 Claude 业务失败，不重复派单或
重握手。文件解析、实时身份、daemon 运行及业务交付分别留证。新版本测试和
发布不热改正在执行的论文任务包或哨兵，原失败及适配记录保留。

- **按收益分工。** 一人可快速完成的整理直接执行；有独立的引文溯源、
  统计输出核查或工具审查时再派给一个或两个已授权 executor。
  每人有独立任务包、nonce、输出目录和完成条件；共享文稿、公共脚本
  只有一个整合写入者。Word/Zotero 等原生资源仍按原队列串行。
  没有独立待办时允许待命，不为显示活跃重估模型或重复审稿。
- **接续时核实际任务归属。** 实时 caller/workspace、原 role-map 与执行者
  当前任务必须对应；标题或旧摘要不能替代。正在审其他章节或另一项目的
  Claude 记为“另有任务”，仍可向已授权原会话及时发送新信息，由接收者协调顺序；
  不称其故障，不抢占共享写入。原绑定跨工作区时，维护联系沿已授权继任入口，
  本任务独立工作按已有授权继续；保留原会话和任务包，不借用他方执行者。
  进度说明当前零、一或两个 executor 的具体原因；在下一次实际派单或既有
  阶段边界再核可用性，不另建监控循环，也不永久沿用旧故障判断。
- **握手只验证通道。** 直接给绝对 pending receipt 和固定完整 skill；
  不在 ACK 前要求业务审计。使用 `--handshake-timeout 600` 或更长预算，
  不用泛化 `--timeout` 覆盖相位预算；有效 ACK 到达立即继续，
  同任务健康握手复用。预算不足或检测器漏观测不能归因 Claude 失效。
- **prompt 与 callback 都核原生全文回执。** 固定同一接收进程/session、
  transcript、新鲜EOF fence和完整正文。新Codex用NATIVE_INPUT_INTENT及
  原thread的一次native steer/start，不读写composer、不按Enter/Tab、不入
  follow-up队列；异常或未知仅观察原次，不重发。Claude终端保留PASTE_INTENT，
  完整原文和结构连续两次稳定后一次提交。只有原fence后新增、逐字相等的
  native user证明收到；RPC接受、Claude queued_command和正文已读不代替。
  历史queued callback保留原controller，不经native重放；详见
  [原次恢复规则](verified-compose-delivery.md)。UNKNOWN、压缩、草稿改变或
  缺原binding/fence不能补键；报告读取不伪造receipt、不换nonce。
- **ACK 后及时交出具体业务。** 握手前备好研究范围、真实输入和验收条件，
  ACK 后补身份凭据并立即定稿、派单。握手已过而包仍是 draft 或尚未提交，
  属于 `SUPERVISOR_DISPATCH_PENDING`，不能称 Claude 停工或失效。
  ACK、定稿、提交、消费分别记录实际时间；压缩接续先补这个已有交接，
  不重握手，不重发已提交尝试。新信息就绪即发送，由接收方协调独立待办；
  压缩导致支持入口不可用时保留该次状态，继续其他工作，不把正常执行设为禁令。
  本条不表示自动派单 hook 已实现，也不允许重复投递同一未知消息。
- **报告完成就沿原入口回调。** 不额外等待 supervisor 空闲，不建秒级
  watcher；由原 bridge 执行首次受保护投递，可能已输入的原 callback
  仅零输入核原次。supervisor 可读固定报告并推进不依赖传输回执的工作，
  回执缺失如实保留。
- **及时处理回复与结算提示。** 0.4.35 的 ANSWERED 提示供原执行者核正文及
  SHA后沿原controller消费；显示不代表已读。原生callback已确认而预留尚未
  RELEASE时，独立CALLBACK_SETTLEMENT提示主管核报告和精确解除，不增加
  下一任务ask_count、不发输入、不代业务裁决。runner在待消费、正式预留或
  观察期限返回，不证明终端空闲或Goal改变；主管核实际边界后接回原论文待办。
  终端续询从上一条原生确认后至少60秒起算，原未确认输入保持只读核原次。
- **正式预留期保留已授权的文件询问。** 0.4.35 新 episode 可由原执行者显式
  `start --continuing --reservation-inquiries`，同时固定总任务、授权文件和
  当前 controller；预留中每60秒写文件 `RESERVATION_STATUS`，携带精确预留，
  询问任务、依赖或回调状态及下一动作/时间。该 runner 的自动终端求派仍暂停，
  旧 pending 保留；双方就绪信息仍可经支持入口及时发送，不要求等待空闲。
  原执行者读完整回复并按SHA消费后才重启该轮；询问不等于派单、接受或RELEASE。
  安装、旧controller和修改既有episode不能追加此权限；未启用者仍按旧规则暂停。
  `run`仍返回 `FORMAL_RESERVATION_WAIT`，文件定时器不唤醒模型；`NO_EPISODE`
  仍不提供预留者、年龄和包状态。普通和continuing的新controller消费均核原生
  执行者及精确回复SHA；真实两轮与自动hook另留验收证据。
- **故障不拖住全篇。** 正常执行可接收新信息；原生 reconnect 缺少支持入口时
  保留原尝试，不通过重启或补键恢复。provider 可重试
  故障仅在原尝试终态后按既有上限恢复，认证/欠费不盲试。持续失效时
  沿已有接管授权保留原会话和证据、确认无并发写入，再由 Codex 继续。
  自审标 `solo_self_review`；恢复后及时联系同一会话，共享写入在明确交接后交回。
- **已接受成果及时结案。** 论文修订、原生检查、审读反馈、传输核收、
  用户验收分别记账。已接受章节或局部工具故障不因经验维护重新开审；
  剩余论文主线另列。新改动只做相关增量核查，保留历史失败与纠正依据。

GitHub 文档更新、安装、客户端实际加载和研究结果验收是不同完成轴。
协作安装器按实际 ownership 处理 wrapper 与 hook：可证明属于本包的实体
目录保留，备份被替换的 SKILL 入口后更新指向固定 release 的 wrapper，保留
其他文件和 foreign 配置，不承诺整目录转 symlink。已有 symlink 依安装计划
更新；owned wrapper 和同版 hook 路径由同一安装器管理。
论文安装器只备份覆盖维护文件，保留章节与私有历史资源，不复制协作 hook。
主管是唯一安装写入者，执行者审独立反例，不同时写共享配置；先按
[安装与回滚](runtime-validation.md#安装与回滚)核来源、版本与哈希，核收后
及时交回下一步或明确依赖，避免重复旧回调。

报告及回调终态后的可执行约束见[有界收口运行规则](executor-closeout-enforcement.md)；
该约束结束 executor 本轮扩展工作，不授论文通过、不补造投递回执。
本页不授权重跑研究、重启会话、额外模型调用或绕过共享资源锁。

## 报告发现与有界等待

报告、任务包和原attempt保留后，沿显式task-bound诊断和原controller
reconcile核原次。所有全局workflow hook均为非阻断observer，不执行旧gate，
不返回deny/block/continue:false。诚实Stop及普通工具始终开放，不据此宣称
未证实的收到或共识。`cmux_supervisor_report_guard.py`供显式冻结报告诊断；
自动PostToolUse只按实际root/child身份提示最多8条文件请求，公平轮转并在
成功flush后更新游标。child不能消费parent收件箱；提示不等于正文已读、
原生接收、论文接受或disarm。

idle Stop 只记录一次状态并允许结束，未求派不阻止 Stop。显式
`executor_ready.py persist` 默认 60 秒、硬上限 300 秒，保留原请求及
原期限，不周期重贴、不因重启延长。主管答复须沿原 bridge 到原 surface
或原请求指定 mailbox，绑定原 loop record。CCC 等待有期限；
native Goal 和论文验收独立核证，通信等待不增加科研审轮。

## 双执行者审查的输入与收尾边界

### 子任务收尾后仍由主管推进整篇

正常报告收尾、回调核收、等待同版 PDF 和 Claude API 故障分别判断。旧
`CALLBACK_UNCONFIRMED` 或自动 recap 不能覆盖新的正式回执；先核原报告、
核收/disarm 记录与当前屏幕，不据旧截图重启、重握手或重做已接受的审查。

主管核收后追加真实状态及具体安排，沿原受保护通道一次同步，也可并入下一项
确有必要的任务交接。状态含原任务及证据路径、业务裁决、回调状态、下一动作、
负责人和触发条件。最终 PDF 未生成时明确依赖及生成者，主管继续生成；若已有
独立待办则及时正式派单，不能只握手后留 draft，也不为保持两窗口活跃造任务。

状态通知与原 callback 独立：通知 queued/unknown 不影响旧回执确认，只读核原次，
不重贴、不补 Enter、不额外索取 ACK。原 marker 已解除后，新的用户状态查询或
主管通知按新授权读取指定证据；当前任务的收口不永久停用会话。不要让用户转话，
不要把子审查完成报告为论文完成。复用协作 skill 的
[核收反馈规则](https://github.com/lzhs1995/multi-agent-collaboration/blob/main/references/efficiency-and-closeout.md#核收后把结论和下一步交回执行者)，
不另建发送器或轮询器；新增文档不代表运行中的 hook 已加载。

派单时把固定研究证据与主管持续维护的导航页分列：前者绑定路径和SHA，后者
注明所有者及观察时间。任务包引用的身份与角色附件必须真实存在；未提供的
可选资料明确标注，不能以占位路径代替凭据。已发送的任务包不得就地补写。

执行者结论按观察时点阅读。主管已经补好的入口记为已解决，不再派一轮相同
核验；真实数据、模型或历史采用上的未知仍单列，不以导航通过替代。主管核收
每条建议的证据和适用范围后继续交付，不要求两名执行者互审所有相同材料。

执行者未注意到派单提示不等于未发送，应查原尝试及完整接收记录。旧任务绑定
的接口文案与当前安装分别核对；面向后续任务修正文档，不迁移在途控制器，
也不为确认修复再次握手。工具修复、报告接受和正式回调回执仍分别记账。

## 共享 daemon 与重复 TTY 的正确归因

共享后台可能继承另一终端的环境；以唯一存活的原生客户端、进程出生信息和
内核读取的 surface/workspace UUID 识别本方，再核该 UUID 对应的真实 TTY。
其他窗口残留同名 TTY 不得否决已明确的本方身份；重复 UUID、实际 TTY 不符、
进程漂移或跨 workspace 仍须拒绝。不得手工覆盖 CMUX 环境绕过核验。
这是 supervisor 客户端识别问题时，应准确说明，不能称“Claude 身份门禁失败”。

同一实际身份必须贯穿发送、活动任务登记、Stop、回调收口和文件租约。
共享后台的旧环境不能让论文任务读取另一工作区的 marker 或忽略本方租约。
协作运行时在每次 Hook 内解析一次 caller，退出即释放；下一次调用重新核验，
不得改环境或跨调用缓存。解析失败明确拒绝，不能降级回旧环境。布尔型
Stop 重入仍先退出，以免把回调收口检查变成新的催促循环。

执行者给出报告及原次回调终态后，主管负责读取、核收和释放该任务；历史
`CALLBACK_UNCONFIRMED` 文字不推翻后续已核实的正式回执。新握手与新任务
分别绑定身份，不借旧任务继续催促。身份补丁、配置安装、实际客户端执行
和论文交付继续分列，复用已完成审阅，不再为旧报告重启一轮工作。

握手只做通道验证，当前 preflight 不运行强制探针。显式诊断中已经输入的测试
token 才按实际长度有界清理，保留逐键身份核验
与最终清空检查；有效 ACK 到达后立即派发，不为状态核查重复握手。两个指定
Claude 可分别核数据链条和工具补丁，独立目录并行计算；同 pane 两 tab 的输入
继续串行。原任务已经入站但检测器未确认时，只核原 journal，不重贴消息。

经验维护须落到新固定 release、实际启动器与 hook，再测安装入口。不能只改
SKILL 文案就宣称故障已修复，也不能把新配置当现役客户端已热加载。等待工具
审查期间继续实体归档核收；不因此增加模型估计、改稿或新的研究审轮。

## 握手清理与等待状态的准确记录

以下仅适用于显式 `bridge-test` 及原次恢复；0.4.46 新 preflight 默认跳过探针，
回执为 `optional-probe-v1` / `NOT_RUN`，清理字段为空，不表示清理成功。
旧失败探针不可套用新能力追改为通过。

协作skill的显式bridge-test使用独立短探针，实际token从evidence读取，不根据长
task id重建。减少删除次数仍须逐键核UUID，ACK继续使用600秒相位预算；
离线回归通过不等于现场速度或成功率已测量。

探针全文不见了不能算清空：剩余前缀和暂时缺prompt glyph都必须被区分。
只有明确属于本token的非空前缀可有界删除；外来文字、排队/运行状态或缺
glyph只有限重读，最终核到空输入区再继续。已有显式force授权的虚拟建议
只可恢复到实际粘贴前文本，不扩大授权。该实现复用协作harness，不复制
另一套hook或发送器。

已发送后的正常ACK等待及原nonce迟到恢复均记为
`AWAITING_EXECUTOR_ACK/PENDING`，不提前宣布Claude失败。原传输异常保留，
实际拒绝/过期仍FAIL，多executor部分ACK不通过。显式探针尚未验证清理时不得
派论文任务；未运行探针的新握手依其独立回执验证，不要求补做探针。
主管继续不依赖通道的实体整理。既有报告/回调已核收时不为测新版本再握手。

## 调度提速与原主管身份的版本边界

协作0.4.40统一历史预留的tick、摘要、scheduler与RELEASE观察：完整核验协议后
保留原已显式登记的文件询问权限；旧episode无该权限时仍暂停，不热改原controller。
工具及hook可以认证实际嵌入式Codex TUI，完整核验原生foreground和进程链；
中间模型CLI、未知包装器不能借继承环境冒用父线程，支持的shell/rtk与叶解释器
保留原边界。control socket与真实投递仍单独验收。

论文技能升级不得原位改写在途包固定的源码或adapter。完整新源码安装到独立版本
目录并核manifest；新任务固定真实路径和SHA，旧任务继续原路径。公共安装器对不同
的已存在受管字节报PINNED_SKILL_OVERWRITE_REFUSED。保留备份不是旧任务兼容证据。

协作0.4.37仅在同一个文件sweep内复用完整release验证，每次复用前核全部成员
及父目录变化，变化后完整重验，下一轮重新开始。身份、登记、授权、STOP、
预留和回件状态仍实时读取；原控制器、未确认输入及消费权限保持原样。
按实际sweep记录full_verifications/reuses/invalidations，再核原回件产生至
发现的时间。只读验证耗时降低不等于整轮或实机延迟通过，执行者读件延迟另计。
沿已有证据只测本次改动，不重跑已接受审查或为实验新建会话、轮询器和任务。

协作0.4.36的嵌入式Codex身份路径仅供原主管使用迟到ACK核收入口，须完整
进程、foreground、UUID、workspace、TTY和稳定复读证据。普通发送与自动hook
认证未由该入口解决；不能借ACK成功放宽其他门禁，也不能让维护者代原主管核收。
Claude Tip行不能掩盖活跃spinner，忙碌、实际草稿与未知布局继续保留。

## 文件管理任务以实体交付收尾

用户要求归档与复现材料整理时，先按章节提供真实数据、程序、初始化模板、模型
和表图，再写简短使用顺序与问题说明。大文件可提供已核验的本地压缩实体或网盘
位置、完整性校验及恢复步骤；不能只交审计Markdown/JSON，也不能把目录阅读顺序
写成整库执行许可。链接可用、文件身份、可迁移运行、历史采用和科学接受分别记录。

对接统计复盘者时，优先核收既有文件请求和结果。当前同名DTA/CSV的SHA一致，
只证明当前文件身份；它不证明旧模型实际使用该输入。保存数据框的逐格匹配也不
替代原执行日志，部分模型的匹配不能扩大为全部模型通过。输入覆盖、竞争版本或
历史缺项应逐项附注，沿用户文件管理范围交人工判断，不为补齐记录启动重估或
改写论文、PPT。用户指定核心程序与旧稿后处理来源分开导航，保留历史依据；
Windows与Mac资料按证据比较，不以所在平台决定优先级。

磁盘不足时主动处理已授权备份与清理，不停止全部工作。按用户空间底线及预计
产物预算准入；大模型逐件恢复，禁止为了核路径而展开整批模型。备份须实际回读
整包和全部内容；由原文件所有者核依赖后回收源，主管核回执并清理自有终态缓存。
已由所有者清理的源不重复删除。实际可用空间与逻辑/克隆大小分列，压缩未释放
空间的失败原样保留，不批量重复。唯一源、现役数据库与运行依赖继续保护。

归档完成、统计插件验收、回调结算和工具维护分列完成条件。后继导航文字不属于
已经上传的旧快照；说明其时间边界即可，不因每次状态更新循环打包、重审或重跑。

### 同一 pane 的原生 Codex 维护通信

0.4.28 的 `successor-rebind-v2` 可显式固定 `transport=codex_native_same_pane_v1`。
授权记录与 artifact 必须同时绑定不同的 `caller_thread_id`、`target_thread_id`，
以及双方 workspace/surface/pane UUID。只允许同工作区同 pane 的两个不同 surface。
调用者必须通过当前原生 foreground 线程认证，接收者必须仍是指定 Codex 进程和线程。
随后沿已认证 control socket 单次 steer/start，保留原 EOF/NATIVE_INPUT_INTENT；
接收不确定只观察原次。此授权拒绝全部终端 paste/send/key，也不放宽普通侧窗格规则。
旧 controller、回调与 UNKNOWN 不迁移。安装、自动 hook 与真实原生收发另行验收。

### 继任握手的时间与证据

- 对既有 Claude 明确指定 `--executor claude`；默认 provider 不能代替已核实的进程类型。
- 在原绑定 mailbox 回应继任身份、用户授权与下一步，同时及时安排正式
  preflight，无须等待原生 Goal 停止或回合空闲。不用新 nonce 重放旧通知，
  共享写入单独交接。
- 同工作区发送与取相同锁的 reconcile 串行；只读不代表不占发送锁。
- 迟到 ACK 先查原 receipt。已有 receipt 时复用原 provider/task/nonce 严格解析，
  保留旧超时证据并重算 validation；不重复 submit，也不删除 receipt 规避拒绝。
- 分别记录原生收到、执行者真实 ACK、主管观测和解析时间。主管晚核收的时间
  属于主管延迟，不能记成 Claude/API 故障。ACKED 与旧 timeout 字段可同时作为历史
  证据保留；当前决策以真实 ACK 与 validation 为准。
- ARMED 表示任务登记。当前 advisory hook 放行普通工具与 Stop，业务接受仍需
  显式独立审阅；不能再宣称 Stop 会阻断等待共识。

### 空间不足时保持推进

按用户原始要求保留至少10GB（10,000,000,000字节）；低于20GB
（20,000,000,000字节）即触发主动管理与备份，20GB不是安装硬底线。
安装须另计源码、临时文件与回滚预算，预计完成后仍保留至少10GB。
低于20GB时沿已有串行百度 consumer
备份终态缓存，回下载核整包SHA及全部成员后才按原权限释放；核实际卷free变化。
不因磁盘不足结束总任务，继续源码、文档和独立核验。保留原件、活动数据库、
原会话、失败证据和系统swap，不启动第二consumer，不降低既有传输门槛。
