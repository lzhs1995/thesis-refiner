# NLM 审查与账号级预算

先做本地可机械验证的字号、编号、表格数值、域结构、PDF 字体/裁切和来源指纹检查。NLM 聚焦长文的结构、内容、逻辑、术语语言及跨页一致性；返回意见须本地裁决。不能把“低幻觉”理解为不会误报。

默认六类审查：理论/方法、数据图文、结构、术语语法、引文、格式。三包方案（前两类合并、结构语言合并、引文格式合并）只有在真实对照证明覆盖与问题召回均无损后才启用；模拟、离线重排回答不证明查询合并有效。对照不足仍用六类，绝不靠降低覆盖节省额度。长附录按实际检索缺口拆分，尾节单独列入矩阵。

正式复核先冻结排版与 PDF。相同 PDF/source 两轮复用，使用独立 conversation；不是每轮重传一次。同主题的定向补问绑定原问题与来源，避免重复做开放扫描。保留所有原回答，即便最终全部判误报。判断“无新问题”依据本地裁决后的新确认问题数，不能篡改回答成空列表。

## 覆盖、检出与正确保留分别记账

完整 source 全文不证明每次回答审读了全文。原生 `references[].cited_text`
只证明暴露的引用内容；缺少某页引用不证明服务端内部从未检索该页。对答案明确
标为“未能核实”的范围，以及本地清单中没有对应审读证据的实质内容，保留覆盖缺口。
不能因回答声称“已检查全部页码”，或把实质页误称为占位说明，就记为完整覆盖。

原生 `cited_text` 出现 `<cited_table>` 时，先检查同一条原生引用的 `cited_table` 结构化表体。保留其行列、列头、数值、单位与来源 ID，再与冻结原表逐格对应；不要只搜 `cited_text` 就认定表格缺失并追加查询。表体存在仍不自动证明答案正确审读了它；语义审读、结构化原引和本地匹配各自记录。没有实际表体或对应单元格时，继续保留具体缺口，不在本地补造远端摘录。

问题检出须同时有错误原文或定位、回答明确指出的问题性质及本地裁决。仅在引用中
出现错误文字、数字关键词相同，或正确验证了局部算术，都不等于识别了跨页冲突。
良性对照分别记录“未被误报”和“经明确审读后正确保留”；零误报不能替代后者。

查询方案对照按每轮完整方案的回答联合计算召回，不要求每个单主题问题检出所有
其他主题的错误。同时列出各主题结果、共同漏检、末节覆盖和良性对照。数值条件
全部达到后，仍需独立裁定范围覆盖；计分程序不得仅凭召回和零误报自动启用三包。
保留六主题也不能免除缺口核查，后续按真实页码/章节锚点做定向复核或来源分片。

## 引用定位错误与实际缺读

先检查本轮完整方案的实际原答和原生摘录，再决定是否还需要补问。如果当前主题已明确、准确地审读对应内容，只是引用编号错位或摘录边界不足，可以联合同轮、同一冻结 PDF 的其他实际回答及完整原生摘录，结合论文定点核验，关闭已被证明的引用支持缺口。保留原问题/错答、原缺口、支持回答的身份、页码/摘录、完整匹配范围和本地理由；明确其他缺口是否仍未解决。

这只改变本地裁决，不重写原始 response/references，不把原 FAILED 回执改成 PASS，也不把另一个主题冒充当前主题。零原生引用、真正没有语义审读、回答明确未核实、原文与论断冲突或只有其他轮次支持时，不能据此自动通过；仍按真实缺口定向补审。source 全文、页面中相同的数字或本地能找到原论文，单独都不能代替 NLM 审读。六主题和同稿两轮完整覆盖不减少。

补审先列原缺口的页码、表/图、需核实的数值或限定条件，再据此组织请求；要求回答区分可核实与不可核实范围，并提供实际原生来源支持。未改稿时沿原版本、主题和轮次补齐该缺口，不重新开放整篇扫描。补问成功只能覆盖其实际审读范围；问题更短本身不能保证完整回答或原生引用。

将“回答自身的错误”与“文稿的错误”分别处置。例如答案把已摘录/剩余单元格数量数错，但实际表值、完整覆盖和原稿核验一致时，保留并纠正本地对答案的解释；不把该回答措辞写入论文，也不因它单独重做已闭合文稿。未证明完整表体已审读时，不能按措辞错误关闭缺口。涉及真实数值、范围、统计限定或结论的矛盾仍须解决。

## 先提取证据，再作定点判断

完整审查的范围以冻结 PDF、任务约定的主题/章节/表图及末节清单为准。
回答简短不等于局部审查，回答很长或列出全部章节也不等于完整覆盖；分别记录
完整范围声明、实际语义支持、仅引用可见、本地已核和具体未核项。定点补问只补
它实际审读的单元，不能替整主题签 PASS；同轮联合支持仍按上节条件核收。

行列密集或易混对象先作可机读提取，再针对已定位内容判断；可在同一有界请求
先输出提取块、后输出结论，勿为格式机械拆成额外调用。记录来源、原标签、列头、
单位、原显示值、角色及锚点；值/标签/百分比跨片段时说明真实对应依据。缺失项
用 null 或未核，不补造远端摘录。模型自核不是独立验证，字段合法也不证明值正确。
JSON 中的 citation 字段不能替代实际原生 references；已有完整答复却没有原生引用时，
保留原答并记录来源验收未通过。若已证原 HTTP 完整终态、进程组排空及既有释放条件，
沿原请求 reconcile 归还，不为缺引用空等或重发；HTTP 终态与内容验收分别记录。
JSON 输出格式本身不证明零引用的原因，服务端终态仍未知时保留原 UNKNOWN。

字符抽取、PDF 视觉表现、DOCX 对象分别核：空格、连字符、上下标、裁切和字号
问题由已有本地渲染及必要的人工/本地视觉审读裁决，NLM 只读文本时不能声称
看到了视觉缺陷。作者自己的术语与被引文献题名、译文版本分开；人名/同年消歧、
物理页/印刷页/引用号须有实际定位。卷期页码、在线年与印刷年等外部元数据仅凭
PDF不能核真，若任务需要核对，沿既有来源政策留原出版记录与版本选择，不能
自动跨版本改年或用数据库更新补写已冻结文稿。
先区分原稿事实错误、出版版本更新与纯样式建议；在线年与正式卷期年并存时先固定
采用的版本。若更新，同步文内作者年份、引文域元数据及文后书目并重新绑定文稿版本，
不能把旧在线记录直接判为幻觉，也不能只改显示文字。

引文样式先核本稿实际绑定的 CSL／样式版本和适用学校规范，再判断作者截断、
标点、排序及年份后缀。未绑定的 APA、GB/T 或审阅者默认习惯只可作为待核建议，
不能直接强加为文稿错误；若两项实际要求冲突，定位具体条款和样式输出再裁定。
同年文献的完整作者名单不同，不足以取消 a/b 等消歧后缀；还须核缩略后文内标签
是否冲突、实际 CSL 消歧规则、条目身份及文后对应，不能只按完整作者名单机械删除。

“未引用”“遗漏条目”须在冻结版本的全文或覆盖所涉范围的完整引文字段索引反查，
核作者异名、缩略、年份后缀及条目身份，并区分正文、脚注和文后书目。检索未命中
不证明不存在；索引范围不全、仅有 PDF 摘录或缓存字段时保留具体未知。需要核真实
库值时复用[原库只读核验](efficient-collaboration.md#原生修订前核真实库值)，
不把缓存缺字段直接当作原库缺失，也不为反查重新 Refresh 或改变文稿。

样本和分组口径逐章、逐模型绑定：记录观察单位、时间窗、有效样本／风险集，以及
分组对象是本人还是配偶、年龄是基期还是当期、区间端点和保存分组的沿用条件。
相同组名或年龄界标不证明各章定义相同，基准样本也不能代替各模型有效样本。
比较矛盾先列两侧定义与适用范围；已明确披露的不同口径应保留，不机械统一。

请求不设置最低问题数，不预告“这里一定错”。有冲突须给冲突双方的原句/表格
单元和范围；没有足够定位、角色或表体时允许限定拒答，并指出具体缺证。
“未发现错误”“明确正确保留”“无法核实”分别记账；不将全部拒答算作高质量。
已披露科学限制不自动成为新勘误，PDF之外且不属任务范围的原日志不新增门禁。

## 有限对照与两轮停止条件

试验前固定案例单元、评分规则、同一 PDF/source、独立新请求/会话及执行器版本；
正确值和既有裁定留在本地评分材料，不能送入待测 prompt 或继承旧答后再称盲测。
保留原 baseline，按共同案例比较精确提取、引用支持、漏项、限定拒答和良性对象
正确保留，并记实际请求、耗时和本地裁决成本。不同范围、版本、时间或无法固定
的服务端模型是混杂因素；两例定点成功不证明全文召回、普遍提速或某单一根因。
需要真错误召回结论时另有经核实的错误对照，不能用全为良性样本估算召回。

同稿两轮要求不因一次 pilot 或没有新问题而减少。第二轮的价值是独立复核范围、
挑战前轮判断并保留正确内容；不得给它标准答案来制造一致。未改稿、已闭合的
局部意见先复用证据，不为第三次确认重开全篇。每轮结束按实际缺口与剩余额度
选择有界定点补核或本地检查；补核仍绑定原版本、主题、轮次，不保证一题自动补齐。
到既有预算/期限或约定试验次数即停止新调用，保留未核范围和真实终态，不能为
取得 PASS 循环询问；尚未达到两轮完整要求就报告未达，有限交付须标明边界。
本规则不改变原预算、UNKNOWN、资源锁、旧 controller 或原次恢复权限。

## 配额事实与策略

截至 2026-09-19，Google [新版公告](https://support.google.com/gemininotebook/answer/17670842?hl=en) 说明从 2026-09-02 起采用 compute-based limits，受 prompt、模型、功能和对话长度影响，5 小时刷新并有每周上限。[旧套餐表](https://support.google.com/gemininotebook/answer/16213268?hl=en) 仍保留部分每日次数说明；[中文指南](https://notebooklm-guide.com/zh/notebooklm-system-limits-benchmarks/) 仅作补充。账号是否已经迁移、剩余额度和可恢复时间以当前 UI/响应为准。

- regime 为 legacy_daily_count、compute_weekly 或 unknown；记录观测来源、时间、时区和原提示。不猜午夜刷新，不以“500次/24小时”作为通用默认。
- 不把并发1解释为官方限制。账号预算共享；并发容量由当前固定执行器的真实证据决定。已验证环境优先使用一个全局租约组内的两路独立 notebook 查询；未绑定此能力的旧入口继续串行。三路以上尚无本机验证，不能只改数字启用。具体依据、降级与接口见 [并发能力与自动调度](nlm-concurrency-and-scheduling.md)。
- 固定 READY 后由可立即消费的协调器准入，准入期限从实际消费开始。短批最多两题，保留有限准入窗口；已准入流使用独立进展超时，不因发消息后的5/10分钟耗尽而截断。每组原网络终态、排空、归还自动连续执行，随后公平选下一组；本地审读不占网络槽。未知终态停止新调用并保留原请求；期限不是释放证明。分别记录 READY、实际准入、原流结束、实际释放、下一次准入及本地裁决时间。
- 明确任务调用预算，已知可计量额度保留 20% 给最终验收与必要恢复。compute 余量未知时只报告观察到的请求数、耗时和覆盖，不把次数冒充计算单位。每次预算调整保留新观测，不能清掉 UNCERTAIN 请求“恢复余额”。
- 相同账号、notebook、操作、文件版本、轮次、来源和 prompt 去重。相同 PDF 上传可跨轮复用，不能误用其他 notebook 的 upload 回执。
- 空控制帧、超时或进程退出不等于服务端请求结束。UNCERTAIN 会隔离账号并保留资源租约；核对原请求终态及 transport 后才能显式 reconcile。可能已受理的失败不退款。
- 限流账号级暂停。到实际提示时间后只有一个必要审查问题充当恢复探针，失败就保留暂停；不通过登录、换账号、新页或改 default 绕开限额。

## 执行入口

需采用已经验证的低层 SDK 传输时，按 [新任务 SDK 入口](nlm-sdk-adapter.md#prepare-a-new-task) 固定完整依赖、实际执行者、账号、已验来源和持久会话。该入口复用下述串行 runtime，不能据此启用两路能力或宣称完整 CLI/MCP 已验证。

`scripts/nlm_runtime.py` 是保留的串行入口，使用 `multi-agent-collaboration/scripts/resource_broker.py` 的共享队列和 OS 锁。它的单在途检查不因文档更新自动变成两路，也不能绕开检查并启动多个旧 runner。已验证两路通过任务绑定的执行器使用同一预算与全局租约，在组内原子登记两条原始请求；现役 pinned 文件保持原字节。新增 `scripts/nlm_ready_scheduler.py` 负责持久 READY、公平选择和消费真实归还，不发网络、不改预算或 broker；接入方式见上述调度说明。

准备私有 binding：账号匿名键、notebook/target、workspace/surface UUID、broker 文件哈希、transport 文件哈希、按 operation 列出的 argv 模板及严格复用标志。`commands` 是已验证 transport 的命令数组，使用 `{notebook_id}`、`{source_ids_csv}`、`{prompt_file}`、`{file}` 等占位；不拼 shell 字符串。

```bash
python3 scripts/nlm_runtime.py configure --account ACCOUNT_KEY --input /absolute/quota-policy.json
python3 scripts/nlm_runtime.py run --binding /absolute/binding.json --input /absolute/query.json
python3 scripts/nlm_runtime.py report --account ACCOUNT_KEY
```

先核查现场 CLI 的 `--version` / `--help`，再固定模板。已观察到 `nlm 0.9.12` 用 `notebook query NOTEBOOK QUESTION`；`notebooklm 0.8.1` 的上传是 `source add CONTENT -n NOTEBOOK --type file`，全文要 `source fulltext SOURCE -n NOTEBOOK --json`（默认文本只显示 2000 字符），没有 copy 命令。文件不存在时可能被当内联文本，因此上传前必须检查存在性与 PDF 签名。不要从一个 CLI 的帮助推导另一个 CLI 的语法。

已绑定 transport 优先于泛用 skill 的自动登录、备用后端或新页面恢复。`NLMUnifiedClient` 明确拒绝未验证的 copy、自动建 notebook 和绕过队列的 batch；备用 CLI 只有单独测量并写入 binding 才可用。通道错误不自动切后端重发。

汇总历史回执时，区分旧格式兼容失败与真实审校缺失。旧失败回执缺少汇总器期望的顶层字段，不应因此重新发送已经结束的请求；可以在任务私有读取层用同一原请求/原流的真实身份字段作兼容，并保存字段来源及匹配证据。不能根据预期值补造身份，不能改写旧失败，也不能用该兼容降低当前成功回答的接收、引用与覆盖要求。

## 全文输出丢失身份字段

`nlm 0.9.12` 的全文 JSON 可能只有 content/title/source_type/url/char_count，
即使底层 `hizoJc` 响应包含来源 ID。不能把请求中的 ID 填回去冒充服务端回显，
也不能因 CLI exit0 或全文看似相同就撤掉来源检查。

已验证的 transport 可在原请求 fully_received、终态回执和原始响应哈希均核实后，
调用 `scripts/nlm_fulltext.py` 的 `normalize_rpc_fulltext`：从服务端响应提取 ID，
核对请求 ID、完整文本、标题和字符数，并另存归一化结果。保留原 CLI 字节及所有
失败回执；本工具不发请求、不改变预算/租约、不把原 UNCERTAIN 改成 PASS。
notebook 归属来自实际请求绑定，不能声称该响应回显了 notebook ID。
没有可靠原始响应时保持失败并核清；已有可验证全文则离线复用，避免重复上传或读取。

## 从审查材料生成音频

用户要求 Audio Overview 时，使用已验收且哈希固定的指定材料，按 [音频生成与验收](nlm-audio-overview.md) 单独记创建次数、artifact、等待、下载和媒体验证。音频不替代六主题审查，技术验收也不等于实际内容听审。审校请求的来源缺口、查询健康暂停和生成类操作的状态分别保留。

已绑定环境发生真实认证或传输失效时，按 [同账号恢复](nlm-auth-recovery.md) 处理；优先级中的“复用原 transport”不应被解释成即使原 target 已消失也永远原地等待。恢复须沿既有授权、原账号与实际资源安全边界，不因此重发旧请求。

## 有界传输诊断与压缩协商

长流超时先分开记录原 HTTP 终态、实际答案进展、编码 payload 字节、解码 entity 字节和本地归档字节。大归档本身不是超时根因；可复用固定成功/失败归档离线测量解析与压缩成本，不重发已提交请求。同账号其他任务的终态与路线记录只能证明该路径曾可用，不能把其题目或身份借给当前任务。

若原私有 transport 强制 `Accept-Encoding: identity`，先核其理由、当前 HTTP 客户端实际解码能力及已有证据。经审定可仅为未提交必要题另绑标准 gzip/deflate 协商，保留原账号预算、source、总期限、单 POST 和 UNKNOWN 恢复规则；不改全局代理、旧 controller 或原次，不自动降级重发。传输恢复仍使用真实必要题，不另造无审校价值的探针查询。

客户端 `aiter_bytes` 已按 Content-Encoding 解码时，不再手动二次解压。分别固定解码后的流实体、原始响应文件和本地归档的指纹，明确各文件所处层次；线上编码 payload 与本地重压 gzip 分别记数。压缩体完整性须独立核验：即使 JSON 已完整，缺 gzip/deflate 终止信息仍不得通过；先用实际固定成功流离线验证 identity/压缩解码等价和截断拒绝，再观察真实响应编码。HTTP 终态、压缩完整性、原生引用与内容覆盖分别验收。

实际恢复后保留请求/回执/字节和期限证据。若同时改变 prompt、路线或其他条件，只能报告恢复成功及实际协商效果，不能将耗时下降唯一归因于其中一项；没有采用压缩时如实记录，不把客户端声明当服务端确认。
