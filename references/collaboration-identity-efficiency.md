# 协作故障分层与效率

握手用于验证通讯，不应演变成反复审查或阻断论文主线。确定性身份拒绝发生在发送之前，不是 Claude 503，也不是执行者停止工作。

1. 先区分进程发现、原生身份核验、输入框识别、提交、接收、成果验收。记录失败在哪一层；不要在本地拒绝后等待 ACK 或重复握手。
2. macOS 名称查询漏掉进程不证明进程消失。协作桥应枚举候选，再核验内核可执行文件、UID、进程出生时间、会话参数、TTY 和 workspace/surface UUID。禁止用焦点或历史编号代替身份。
3. 外部 helper 不兼容时使用协作 skill 自带的受保护 bridge；保留相同门禁。不得用裸终端发送绕过检查。
4. Enter 后读回。compose 残留、排队、实际接收分开记录；不确定投递保留原 journal，只观察，不重贴。ACK 和成果 callback 分别验收。
5. 零、一、两个执行者按独立任务量决定。繁忙的原会话不插队；两 tab 共一 pane 时串行输入。执行者持续失败时沿用户授权转单 agent，继续安全的主线工作。
6. 修复分别报告源码提交、固定安装版本、launcher、客户端 hook 配置和真实收发。写入配置不等于现役客户端已重载；不改写在途控制器或其不可变版本。

复用 multi-agent-collaboration 的 `references/native-caller-inventory.md` 和对应身份回归测试。论文 skill 不复制传输实现，不给冻结成果增加无关审轮。一次现场成功不能保证永久无故障；回归测试、明确归因和有界恢复用于避免同类故障反复阻断交付。
