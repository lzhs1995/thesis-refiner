# 全文格式经验沉淀与本地裁决

适用：多章统稿、学校格式对标、完成后的经验总结，以及据真实故障升级检查器。保留用户的目标稿、允许修改范围、格式偏好和完成条件。已经冻结的论文只作证据；经验工程进入新任务目录，不重排原稿、不重新估计模型、不沿旧额度重复审读。

## 规范与工程的分工

OfficeCLI 的 [全文统稿指南](https://github.com/lzhs1995/officecli-word-revision/blob/main/skills/officecli-word-revision/references/full-thesis-formatting.md)、[规则来源矩阵](https://github.com/lzhs1995/officecli-word-revision/blob/main/skills/officecli-word-revision/references/ruc-rule-sources.json)和[整稿契约](https://github.com/lzhs1995/officecli-word-revision/blob/main/skills/officecli-word-revision/references/thesis-integrity.md)是格式实现入口。执行时优先读取实际安装的同版资源，并固定其提交/文件SHA；不要让远端 main 的后续变化覆盖当前任务依据。

| 类别 | 处理 |
|---|---|
| 学校/院系明确规定 | 保存原文、日期、出处和适用对象；映射至具体 profile 属性 |
| 用户明确要求 | 保存原句与范围，可覆盖本 skill 的默认建议；不要重新要求授权 |
| 工程或审美选择 | 说明触发、效果、代价和验收方式，避免升级为普遍校规 |
| 未核实、矛盾或缺失规定 | 保留不同解释和影响；不自动改稿，真正未决时最后交用户决定 |

RUC 当前基线来自用户保存于2026-03-07的规范快照，不能称为最新官网规则。本轮已完成四主题与一次窄补问，共5次真实返回、71条原引与33项作者裁决；见[公开审议记录](https://github.com/lzhs1995/officecli-word-revision/blob/main/skills/officecli-word-revision/references/format-review-decisions.md)。用户随后明确保留标题段前/后章50/80、一级50/50、二级20/20pt，并选择新稿前置页大写罗马I/II/III；后继同一用户任务沿用这项约定，旧任务固定profile和冻结论文不改。学校解释不足与用户已作选择分开记录，不重复询问。软件版本、格式 profile 版本、作业 schema 和论文版本分别记录。英在前、中在后及完整拼音排序是项目要求，不能泛称为学校统一规定。

## 对实际统稿问题留证

每个有价值的经验记录：现象与触发 → 原文件/失败证据 → 根因或尚不确定的原因 → 最窄修复 → 实测结果 → 可复用范围。公开部分只保留通用原理、检查代码和合成示例，原论文、执行日志、账号和现场路径留私有。检测器误报也保留原FAIL，修判定后另存新回执，不改正确正文来迁就错误检查器。

对摘要、目录、图目录、表目录、章节、参考文献和附录建立内容块映射。新章另起页可用分页；只有页码制度、页眉页脚、方向、首页设置、分栏等改变，或模板/用户明确要求独立节时才需要分节。六类页眉页脚链接分别检查；新节不等于断开链接，不等于页码重起。已有合理节边界不按“冗余空段”批删。

图表需有稳定对象ID、题注及实际引用绑定；定位时排除三目录中的同名缓存。章内显示号由SEQ等域管理，移动后重新核引用、顺序及目录。表题与首行绑定、图片与图题绑定；图题 keepNext 不应无条件拖住后文。美观判断考虑版心、标签可读性、行高、表头、长行和空白；独占页不自动构成错误。正文注释使用页底原生脚注，默认和逐节重编号都核。

主稿活引文合并后只保留一处主稿活书目，并查静态局部书目残留。保存书目语言、显示姓名、完整拼音/字母排序键及来源；同首字母仍需完整排序，多音姓和机构作者需核实。不要为排序修改作者显示姓名，也不能用手改XML缓存冒充Zotero原生Refresh。宏被受理、Word回写、保存重开、PDF显示各自留证。

## 与 NLM 讨论规范解释

用户请求NLM讨论时，先固定不含私有附件的审议材料：规范原文、技术依据、当前建议及真正争点。原执行者按已授权预算与共享队列调用，来源上传、全文核收、问题返回分别记账，不重新注册已经存在的来源，不重发未知请求。技术规范讨论是独立任务，不授予论文或PPT审查轮次信用。

可按内容组织问题：①分节/页眉页脚/页码；②目录、题注、交叉引用、脚注和书目；③图表尺寸、排序及分页；④附录与电子发布。主题和数量由本次需求决定，不能把一次四题样例固化为所有任务的强制门槛。

对每份原答保留问题、原响应、平台引用编号、来源ID、原引用文字和返回终态。逐条对照固定材料：

- 明确事实与建议分开，NLM不能替学校制定要求。原引能匹配也不证明答案自报物理页正确；本轮补答多处把WORD-NUMBER或DRAFT页码写错，须按本地页图/文本重新定位并保留错误原答。
- 目录命中不等于正文原文支持。保留错配的原编号引用；同次返回的 semantic-search 段落可单列 `transport_semantic_search_excerpt`，核原文后辅助裁决，不能把它改名为原最终引用。
- 原PDF提取存在印刷连字时，仅记录明确的fi/ff/ffi等映射，逐页顺序核对；保留初次严格失败及原字节。不要用删除任意标点、数字、负号或整段文本的宽泛归一化伪造全文全等。
- 表格原生引用可能在 `cited_table` 中，须核表头/行列/值，不能只因普通文本为空宣布无据。
- 新证据不足时只追问真正争点；已被本地原文证伪的建议据证拒绝，不为凑共识无限复问。

裁决表至少列：问题ID、来源与定位、NLM主张和引用、作者核对、接受/限定接受/拒绝/未决、实现位置、影响。真正未决项汇总两种解释、证据差异、推荐及版式影响，最后报用户；确定部分继续完成。某项保留为可配置选项不等于已获用户选择。

## 复用现有验收轴

可选 `thesis_integrity` 通过绝对路径＋SHA绑定到OfficeCLI作业。它是只读结构检查，覆盖声明的内容块/逐节页码与链接、三目录、复杂/简单/嵌套域、脚注、题注配对/顺序、真实书目显示顺序及指定图表。省略的领域须在报告中列出。条件表格样式、审美、引用语义和拼音读音仍需本地审读；不能把结构PASS当成全文通过。

消费原生保存后的DOCX再运行结构检查，随后核真实PDF字体、图表和三目录的目标页。字段刷新与分页可在有限次数内比较连续两次页数/目标页结果，稳定性是证据，不能单独证明正确。若只是检查器误报且文件字节未变，修复检查并重验，不重导出已经正确的PDF。

脚注设置曾在Word保存后消失，须核实际逐节有效值；同一节不同页的两个脚注可区分每页和每节重启。目录更新只改变自动 `_Toc…` 名称时，保留原快照并比较真实目标位置/文字、域缓存和内部链接。不能简单删去名称，也不能只匹配相同标题或采用会随run格式变化的XML节点序号。书目文字与顺序通过后，还要核每条实际独立成段；一个文本节点中的换行符不保证Word生成两个书目段落。合成样例对这些机制的验证不代表已运行原生Zotero或完整学校模板。

仍使用 [checkpoint](checkpoint-contract.md) 的既有 `native`、`format`、`visual`、`pdf_fonts`、`zotero` 和 `export` 轴。`format` 回执可引用整稿报告、profile、规则矩阵与作者裁决，但只有实际验收完成且绑定最终DOCX时才能记 `mode=real/status=PASS`。不要直接把合成或 `read_only_structural` 报告改名为完整原生格式回执。格式经验任务本身无需伪造完整论文checkpoint来结束。

## 发布与安装

附录范围、版本、卷内页码、正文引用和文件清单分别核；学校需要的实物不能未经确认用GitHub链接替代。通用代码/合成示例可以公开，固定提交、资产和下载SHA，许可分开说明。tag/普通Release不天然不可变；实际归档或DOI只据真实配置填写。封包回读成员集合、大小、CRC和SHA；回执可写在冻包外，不为同事新回执重复封包。

安装按 [运行时维护](runtime-validation.md) 使用同一写锁、dry-run、当前源核对、备份及回滚记录。其他任务的固定Word/NLM脚本不覆盖；新版可隔离安装，后继任务显式路由。报告区分源码发布、本机安装、自动测试、真实原生验收及现役采用，缺哪项就明确保留哪项。
