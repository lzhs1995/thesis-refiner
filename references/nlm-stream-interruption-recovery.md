# 源站响应后断流：核收原请求并自动接续

本流程适用于源站响应已经开始，随后发生读取超时或 `RemoteProtocolError: Server disconnected`。它沿原执行者、原账号、原请求和现役资源管理器执行。已有恢复授权直接沿用；文稿裁决、来源核对和不占用故障资源的本地制作继续进行。

## 本地接收期限与网络错误分别核实

`asyncio.wait_for(iterator.__anext__(), idle_seconds)` 的到期会取消本地读取；即使随后关闭客户端，也不能证明远端任务已结束。一条实际请求在收到响应后触发180秒无新字符期限，同组另一条完整返回；该窗口的系统日志没有换网或睡眠记录，代理连接日志又缺少对应覆盖。可以确认本地期限触发，不能确认服务端中止或唯一根因，也不能将旧的换网原因套用过来。

对需避免过早取消的后继绑定，可使用 [有界原流等待器](../scripts/nlm_stream_wait.py)。它把无字符期限作为一次本地告警，保留同一个 pending read，直到原数据、EOF、真实异常或既有总期限到来。示例策略为180秒无进展告警、300秒首数据告警、900秒总期限；这是当前有界配置，不是官方服务限制。响应头阶段的连接期限由原传输单独控制，不能顺带扩大连接重试。

```python
deadline = StreamDeadline(started, absolute_seconds=900,
                          idle_seconds=180, first_data_seconds=300)
chunk = await await_stream_operation(
    lambda: iterator.__anext__(), deadline, state,
    on_observation=save_local_observation,
)
```

`state['chars']` 必须来自原接收器实际累计字符数。告警不会重置总计时，不调用状态接口、不重新创建读取任务或发送POST；等待停止后仍按原流程保留原字节及未知终态。通知回调只写本地观察。旧组件和进行中的读取保持原字节；先在私有候选验证正常EOF、告警后续流、总期限、真实断流和取消清理，再由原执行者在真实归还边界固定新依赖。候选测试通过只证明等待逻辑，是否实际改善长答仍看真实运行，不能称为网络永久稳定。

## 先复用当前绑定，避免重复定位接口

从任务当前的 transport、请求 envelope、原请求体哈希和已验证的客户端协议说明加载原状态/历史读取器。记录 query 请求 ID、发送时 chat session ID、返回的 conversation ID、turn ID，不能因它们都是 UUID 就互换。状态接口要查询发送时会话的，必须使用发送时会话。

优先直接核发送前保存的原 session 与 body。旧捕获仅留请求体哈希时，可用原 envelope、固定 recipe 和原 profile 在本机内存重建；只有字节哈希完全匹配才采用候选 session，不输出凭据、不重 POST。字段位置或状态码语义有漂移时再核当前协议，不能把历史常数当永久接口。

现有一次真实恢复使用原客户端的状态 RPC `oXwmh`，参数为 `[null, original_session_id]`；历史 RPC 为 `khqZz`。`[null,1]` 的 IDLE 含义由该任务固定的客户端代码证明。这是复用现役接口的例子；调用仍经原 transport 的完整参数与资源边界，不能靠复制这几个字段构造新的独立执行器。

## 一次完整核收

1. 保存首次异常、响应头、所有原始字节、完整帧与未完成尾部、原进程结果和租约。暂停故障路径的新 query 准入，保留原消耗。既有历史健康记录不解除当前隔离。
2. 离线检查实际主答案字段、原生引用和真实结束标志。名义上的 answer/type-1 帧可能只有嵌套思考或搜索材料；主答案为空时，不提取嵌套文字冒充正式答案。字节数很大、HTTP 200、解析器未报错都不足以表示完成。
3. 在原资源所有权下，对每条身份已核实的原会话做一次必要的状态读取；保存源站 HTTP 与未过滤 RPC。忙碌或无法解释的结果保持未知；不自动取消、不换 session、不用新 query 探测。需继续观察时遵从该实际状态和原执行器的有界等待规则。
4. 状态允许后，各读一次原 conversation 的历史，尝试收回完整原答与原生引用。历史有完整答案时保留其实际出处和请求对应；不得据片段拼造终稿。历史为空只说明未取回答案，不能单独证明服务端已结束。历史读取在 TLS 阶段失败且没有 HTTP 响应时，记为 `UNAVAILABLE`，不可填空列表。确认恢复窗口后，可沿既有授权对同一会话做一次有界只读恢复，保留首次失败与实际返回；这不是重发原 query，不增加审读轮次或退款。
5. 原会话已证实 IDLE/终止、本机原调用和进程已结束、锁及租约状态已核清时，由原协调器完成归还。无有效答案就归还 FAILED，原 UNCERTAIN、响应字节、消耗和失败经过仍保存；不退款、不复用已计账请求 ID。
6. 健康保持恢复暂停，固定一条**已经授权但尚未提交的必要题**作单题恢复。用现有预检兼容原证据，真实完整答案和所需原生引用返回后自动继续既有容量/公平队列。待处理题不重复入队；原失败内容只按明确的最窄补答授权另立新 ID，不能自动循环所有失败题。

原有读取器、状态解释、身份核验和归还接口可复用时，直接填本次原请求参数与证据；不要重做已验证的 SDK、整库全文或网络配置。保持来源接入、query 健康、资源归还和论文内容接受各自的真实状态。

## 诊断与恢复分别报告

同步保存故障窗口的 UTC 起止时间和本机时区。核已有代理、系统网络切换、睡眠、进程重启日志是否真正覆盖该窗口；窗口缺失、日志轮转或无事件不能证明某一层没有故障。若缺少覆盖，在下一条必要任务前沿原配置准备有界观察，不为取日志改全局代理或发额外测试题。

只有同一时间的原始证据支持时才归因于代理重启、节点切换、TLS、协议协商或服务端中止。后来四组 TLS 对照成功只证明后来握手可用；它们不能解释早先响应后断流。恢复成功也不等于永久网络稳定。

### 请求期间发生断链或换网

先沿原绑定执行者读取已有系统日志，统一请求开始、首次错误和系统事件的时区。macOS 中将 `en0 INACTIVE`、旧地址移除、`Wi-Fi switched networks`、新地址绑定组合定位，可证明接口断链及换网；一次 `roam`、电源由交流转电池或 `Proxy-/Proxy+` 单独不等于睡眠、代理节点切换或源站故障。不要把请求失败之后的跨应用 reset 倒置为该请求的触发原因。

一次实际案例中，两条请求开始后约48秒发生接口断链和换网，原响应分别在约184秒与191秒后记录断流。原窗口没有实际 Sleep/Wake 正证；代理节点日志缺少该窗口。结论是“在途网络变化已证实，唯一根因及代理节点变化未知”，不据相关性补造因果。

恢复和减少重复故障按以下顺序执行：

1. 由原执行者复用当前接口、路由与代理绑定。下一条必要任务前可只读保存接口地址和默认路由快照；有换网证据时给原请求窗口留一份有界系统日志。该记录只辅助诊断，不新建账号级门禁、测试 query 或循环连通探针。
2. Agent 控制范围内不要在长响应在途期间主动切换 Wi-Fi、VPN、节点、全局代理或升级客户端。网络已经自行变化时，不切回旧网络重放原 POST，先依本流程核收原会话。此规则不要求用户为了恢复重复操作网络或登录。
3. 需要等待接口恢复时继续本地审阅；读到实际路由可用后，由原健康状态机准入一条已经授权的必要请求。接口恢复、TLS成功及普通 RPC 成功不替代该题完整答案/引用返回。成功即恢复已验证的容量，保留失败记录。
4. 防睡眠仅在当前任务有实际需要且已授权时绑定自有运行进程；它不能解决 Wi-Fi 漫游、换网或代理重载，也不能用来解释没有睡眠证据的故障。对持续抖动不反复消耗任务：保留暂停与最新证据，继续能完成的本地交付。

### 同机网络任务的验收窗口

先确认同机是否已有负责 Wi-Fi、VPN、代理或客户端连接修复的会话。存在时协调其实际操作窗口，复用原网络任务及原 NLM 执行者，不另建恢复执行器。已授权的恢复和窗口交接直接推进；无需让用户再次确认相同操作。

1. 网络任务在请求窗口前继续只读观察。NLM 执行者等当前已提交的长答真实结束并归还；后继组已经开始时等该组，不取消、kill 或热换其固定组件来制造空闲。
2. 在既有调度锁内核清本账号的 STARTED/UNCERTAIN、活动租约组与原调用进程，并用现成准入暂停机制暂缓下一组。回执记录实际检查时间、原配置、仍为 READY 的 ID 和暂停所有者；不能由单一进程退出、旧 HEALTHY 或口头承诺推导无在途。
3. 把这份真实空闲回执交给原网络任务后，才开始其已授权的解除/重锁或主动断线验收。网络任务结束后返还实际 SSID、接口/路由及现有锁定机制的 active/verified 状态，并明确后续是否仍有主动断线操作。普通上网检查仅证明当下连通；不把它当 NLM query 成功。
4. 原 NLM 执行者收到实际完成回执后，在同一准入边界复核并恢复原暂停前配置，只消费原 READY。两分钟等预计时长过去不是完成证据；网络任务后续的只读观察无需阻止审读。网络维护暂停与 query 健康暂停分开，不能用解除前者清除后者。
5. 若已有查询健康暂停，按既有状态机用一条已授权未提交的必要题恢复；若健康未受影响，接续原队列。完整答案、所需引用、真实归还和恢复后下一组准入分别记录，不增加探针题或重传来源。

一次实际接续中，必要单题完整返回后，原队列在无在途状态下让出窗口；网络任务完成五项现场检查并保持目标热点，作者另行只读核实了连接及锁定状态。此案例支持窗口交接流程。热点策略的具体配置、操作身份与现场证据保留在该任务目录；本 skill 不要求所有机器禁用全部网络，也不自动修改用户网络设置。

这套措施提供可复用的诊断、隔离和自动接续；它不承诺外部网络永不掉线。实际运行应分别记录本次是否采用了接口快照/窗口观察、必要题是否成功、原队列是否已继续。

2026-09-25 的一次实际核收中，两份响应各有18个名义答复帧，实际主答案为空，较大的数据量来自思考/搜索材料。核实发送时会话后，各一次状态读取证实 IDLE，各一次历史返回空列表。两题随后真实 FAILED/RELEASED/RETURNED，0重发、0取消、0退款。下一条必要 query 的真实恢复单独记载，不能由这次归还推断已恢复。

记录最少包含：原失败与原字节、协议/解析器版本、身份核验、状态与历史原 RPC、原调用/锁/租约归还、消耗保留、单题恢复原答/引用、随后第一组实际准入。真实任务材料与账号路径放私有任务目录；公开 skill 只保留流程和可复用接口知识。
