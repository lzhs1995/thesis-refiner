# 以实际交付衡量协作效率

本指南用于既有实证材料的有限复盘和归档，不自行新增统计、模型、稿件修订或审查轮次。协作传输、身份与回调继续遵守 multi-agent-collaboration；本页是工作安排建议，不是新机器门禁。

## 从章节采用终点安排工作

先复用归档负责人已经核定的各章采用文件与来源身份，固定输入输出关系，再追踪相应清洗程序与原始数据。同一程序服务多个章节时执行公共上游一次，按真实依赖接续各章分支；不因分章交付重复运行同一成功阶段。

两位已授权执行者可以分别检查“采用终点与程序覆盖”和“运行结果与历史文件比较”。各自有独立任务、输入哈希、回传标识和隔离输出目录。原生共享应用由明确的一位执行者串行操作，supervisor 负责核收和整合；只读复核不能修改冻结成果。

## 每个复核任务都有停止条件

任务包列明需要回答的问题、核验对象、必要检查及完成条件。区分实证缺陷、来源未决与改进建议。已经核收且输入、范围和依赖均未变化的证据直接复用；仅有通知重复不触发新一轮审查。

历史结果不一致时，先交代哪个文件、哪些键、变量和值不同，再按任务范围做有限归因。足以定位的问题以作者可理解的注释和差异表交付；不为消除差异擅改作者公式、删样本或无限追查历史版本。未解决的来源和科学判断明确交人工。

复核报告应帮助交付真实程序与数据。记录找到文件、原生运行完成、数值一致、来源确认、科学判断等不同状态，不能用工具返回码或同事 DONE 代替全量复现验收。

## 主动派工与有限复核

在已有交付节点检查两位执行者的真实状态；原任务安全结束且有必要的独立工作时，主动派发，不等用户催促。没有独立工作则明确待命，不为维持忙碌新增审轮。握手请求送达不等于正式派工；有效 ACK、任务包定稿与实际提交分别核验。

每位执行者单独判断可用性，不能用另一位或历史 API 错误推断全体失效。上下文压缩进度仍在增加时继续原会话；原消息已收到但检测未确认时观察原 nonce，不重复粘贴。supervisor 同时推进不依赖该复核的真实数据交付。

任务包限定问题、检查预算和停止条件。复核若不断增加探针，安全边界上收敛为有证据的发现与明确未决项，不无限追查。耗尽预算不等于通过，也不允许抢占在途写入。持续失效沿用户已有授权冻结执行者写入后单 agent 接管，保留原会话。

## 回调排障不得挤占复现主线

报告完成、消息提交、实际收到、内容核收分别记账。按原次投递证据有界恢复；未知或排队不重发，不制造回执。业务报告可独立裁决，但正式回调和任务门禁仍按协作协议结案。执行者保留结果，传输问题由 supervisor 接管，其他独立工作继续。

两位执行者不必始终忙碌。上一任务安全结束后才派下一项有用工作；没有独立工作时可以待命。持续失效时按用户已有授权冻结写入并由 supervisor 接管，保留原会话，不能因协作失败终止整个任务。

在已有交付节点记录审查推进了哪项结果、发现了什么实质问题，以及协调是否拖慢交付。不要为衡量效率另建频繁轮询。经验维护单独提交通用文档；不上传私有研究文件，不改变在途绑定，也不把文档发布称为现役客户端已加载或故障永久修复。
